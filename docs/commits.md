> 一个让金色增益完全没用的逻辑错误，以及所有高速流派都会遇到的穿模。

### Summary

```
v2026.10.06.4 深度审查批修 15 个 Bug：Boss 竞态 / 飞升失效 / 子弹穿模
```

### Description

```
高价值修复
· Boss 死亡与升级弹窗同帧 → 主循环顺序调整（碰撞先于 progress）。
  旧顺序下 progress 先弹三选一，combat 随后仍打死 Boss，
  addXp 因 state!=='playing' 直接吞掉这笔 Boss 经验，
  死亡演出还会被 upgrade 状态永久冻住

  后期命中积累才是主要伤害来源，实际倍率远低于面板承诺

  而期望 {dot:true} 对象，opts.dot 读不到，引爆被当成普通命中

· 电弧打回原目标（不排除刚命中的主目标）

· 最高分两处来源不一致（starstrike.high 与 stats.bestScore 各读各的）
· 刷新页面丢累计击杀（新增 pagehide / visibilitychange 落盘）

· 面板弹道数少算（漏 frontLanes / mirror / 散射期临时弹道）
```

## v2026.10.06.3

> 第四批：一次专门的找 Bug 行动。新写的两个随机化测试工具挖出 5 个真 Bug，
> 其中一个是必崩的严重问题。

### Summary

```
v2026.10.06.3 修连环爆炸必崩等 5 个 Bug，新增模糊与混沌测试
```

### Description

```
严重 Bug：连环爆炸 100% 崩溃
· 爆裂弹 + 一群挤在一起的敌人 = 当场崩掉整局
· 根因：areaDamage 边遍历下标边打伤害，而 E.damage 会 splice 列表，
  击杀又递归触发爆裂弹 onKill —— 一次连环爆炸缩短好几格，
  外层循环下标失效，读到 undefined 崩在 en.x 上
· 26 只敌机挤在一起时第 1 次尝试就复现
· 修法：先快照命中的目标（存引用），再逐个结算（下标每次重查）
· combat.js 的 splash()（等离子溅射）写法一模一样，同样会崩，一并修
· 顺带把全项目 14 处"按下标取数组元素"都补上空值检查

其余 4 个
· 虚空掠夺者根本不瞬移 —— blink() 直接改 bs.x，被每帧游走公式覆盖。
  改为反解 sway 相位。修完 599 次位移 100% 换到另一侧（修前是 0）
· 未知道具类型崩溃 —— spawn() 宽容而 apply() 严格，配错就崩整局
· 主菜单战绩不刷新 —— 只在启动时渲染过一次
· 中途退出不记录最高关卡 —— 只有"打死"才记

体验修补
· 过载掉血加 ⏱ 飘字（以前血条凭空消失）
· 细线模式保留元素颜色 —— 后期 1500 发子弹时曾经全场白线，
  看不出自己是等离子还是霜冻

新增两个测试工具（已接进 CI）
· tools/fuzz.js   不变量模糊测试：随机构筑 + 随机输入，
  每帧查异常 / NaN / 数组泄漏
· tools/chaos.js  生命周期混沌测试：随机暂停 / 送死 / 重开 / 拾取，
  查状态机、暂停是否真的暂停、生命值溢出
· 都支持 --json 与非零退出码

工程
· 冒烟测试 498 → 516 项，新增的全部是上面这些 Bug 的回归断言
· 测试台 Canvas 桩新增属性赋值录制（strokeStyle= 等）
```

### 说明

> 那个必崩 Bug **只靠读代码很难发现** —— 要"嵌套爆炸恰好删掉足够多元素"
> 才会触发。是模糊测试跑了 8 次才命中 1 次抓出来的。
> 这也是为什么要专门为它写随机化工具，而不是继续加手写用例。

## v2026.10.06.2

> 第三批：一次完整体检发现"敌人血量是指数、玩家伤害是加法"，
> 后期必然打不动。这批围绕它修，外加体验与工程补齐。

### Summary

```
v2026.10.06.2 击破奖励 + 超时过载修后期难度，新增图鉴与跨局存档
```

### Description

```
后期难度曲线（核心）
· 体检发现：第 10 关 Boss 要打 99 秒、第 20 关 137 秒，12 分钟只能推到第 20 关
· 根因：敌机血量 ×1.2^关卡 再叠每十关 ×2.2 台阶（乘法），
  而玩家强化是加法且很快点满 —— 两条曲线必然发散
· 新增「击破奖励」：每击破一位 Boss，伤害 ×2（永久、可叠加）
  这是一条独立的关卡进度乘区，同时作用于子弹与持续伤害
· 修复后：第 10 关 Boss 53 秒、第 20 关 43 秒，12 分钟能推到第 27 关
· 新增「超时过载」兜底：Boss 战打满 10 分钟后每秒掉 2% 最大生命
  → 任何构筑都不会出现打不完的僵局

图鉴 / 玩法（新文件 js/codex.js）
· 主菜单新增入口，三个标签页：玩法 / 增益（113 个）/ Boss（6 位）
· 数据从 POOL 与 ROSTER 现读，以后加内容自动同步

跨局存档
· 原来只存最高分，现在额外存最高关卡 / 累计击杀 / 击破 Boss / 局数
· 主菜单与结算界面都会显示；损坏的存档安全降级

修复
· 面板在小窗口会盖住玩家 → 自适应：先压扁行高、再按重要度截断并提示
· 生命值显示 '♥'.repeat(1e9) 会 RangeError → 封顶并改用 ♥×N
· 13 行模块启动日志刷控制台 → 收进 Game.log，默认静默（?debug 打开）
· CI 注释写死的"313 项" → 改成不写死

舰队流
· 僚机开始吃「命中积累」，但只有本体的 25%（和数值继承同比例）

打包（tools/build.js）
· 新增源码 zip 生成（内置极简 ZIP 写入，零依赖）
  之前那个 zip 是手工打的、缺了全部新内容且没有生成脚本

工程
· 冒烟测试 456 → 498 项
· 测试台 DOM 桩补上 querySelectorAll / dataset，新增 fireWindow()
```

## 下次提交怎么写

**Summary**（一行，必备版本号）

```
v2026.10.08 一句话说清这批最重要的改动
```

**Description**（按"改了什么 / 为什么"分块，用 `·` 起头，别超过一屏）

```
模块名：一句话概括
· 具体改动
· 具体改动

修复
· 症状 → 根因 → 怎么修的

工程
· 测试 N → M 项

```

写完之后：

1. 把两段一起贴进 GitHub Desktop
2. 同时把内容整理进 `../CHANGELOG.md`，并在本文件追加一节
3. 同一天再发一批就递增补丁号（`.1` → `.2`），并在上面的表里加一行
